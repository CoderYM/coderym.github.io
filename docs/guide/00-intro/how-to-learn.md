# 如何使用本站学习

::: info 学习目标
- 了解本站的整体结构：16 个模块、4 个篇章，以及实战项目、论文、面试等板块
- 根据自己的背景选择合适的学习路径
- 学会使用代码语言切换，并准备好运行示例代码
- 掌握一套「读 → 跑 → 改 → 测」的学习方法
:::

## 站点结构

本站内容分为两大部分：**知识库**（按模块系统学习）和**配套板块**（项目、路线、论文、面试）。

```text
MaxAI Agent Lab
├── 知识库 /guide/              16 个模块，4 个篇章
│   ├── 基础篇  00 导读 · 01 编程基础 · 02 大模型原理 · 03 大模型 API
│   ├── 核心篇  04 提示词 · 05 Tool Calling · 06 Agent 循环
│   │          07 上下文工程 · 08 记忆系统 · 09 RAG 知识库
│   ├── 生态篇  10 MCP 与 A2A · 11 框架实战 · 12 多 Agent · 13 Coding 与 Computer-Use
│   └── 工程篇  14 评估与可观测性 · 15 安全与生产化
├── 学习路线 /roadmap/          三条路径 + 12 周计划
├── 实战项目 /projects/         10 个由浅入深的项目
├── 论文精读 /papers/           Agent 领域的关键论文
├── 面试题  /interview/        基础、RAG、工程与系统设计
└── 术语表  /glossary           常见术语中英对照与解释
```

四个篇章的定位：

| 篇章 | 模块 | 解决的问题 |
| --- | --- | --- |
| 基础篇 | 00–03 | Agent 是什么；需要哪些编程基础；大模型怎么工作；API 怎么调用 |
| 核心篇 | 04–09 | 构建一个 Agent 的核心能力：提示词、工具、循环、上下文、记忆、知识库 |
| 生态篇 | 10–13 | 协议（MCP、A2A）、主流框架、多 Agent 协作、编程与电脑操作类 Agent |
| 工程篇 | 14–15 | 让 Agent 可评估、可观测、安全、可上线 |

核心篇是全站的重心。特别建议先**不用框架手写一遍 Agent**（[06 Agent 循环](/guide/06-agent-loop/handwritten-agent)），再去学框架。理解了底层循环，框架只是语法糖；跳过这一步，遇到问题时很难排查。

## 每篇文章的结构

知识库里的文章结构基本一致：

```text
学习目标 → 概念讲解 → 可运行代码 → 常见坑 → 小测 → 延伸阅读
```

- **学习目标**：读之前先看，读完回来对照，检查自己是否真的掌握。
- **常见坑**：来自实际开发的经验，值得在写代码前看一遍。
- **小测**：先自己思考再展开答案。答不出来，说明需要回头重读对应小节。

不同背景的读者不必从头读到尾。[学习路线](/roadmap/) 给出了三条路径：

| 路径 | 适合谁 | 建议顺序 | 详情 |
| --- | --- | --- | --- |
| 零基础入门 | 编程经验较少，或第一次接触大模型开发 | 00 → 01 → 02 → 03 → 04 → 05 → 06，配合项目 01–03 | [零基础入门路径](/roadmap/beginner) |
| 工程师 | 有后端或全栈经验，想把 Agent 用到实际项目 | 00 速读 → 03 → 05 → 06 → 07 → 09 → 10 → 14 → 15 | [工程师路径](/roadmap/engineer) |
| 架构师 | 负责技术选型、系统设计 | 00 → 07 → 11 → 12 → 14 → 15，结合论文与系统设计面试题 | [架构师路径](/roadmap/architect) |

无论走哪条路径，都建议把 [实战项目](/projects/) 穿插进来。读完 05 Tool Calling 就去做 [天气日程工具 Agent](/projects/02-tool-agent)，读完 06 就去做 [手写 ReAct Agent](/projects/03-react-agent)。**只读不写，很难真正掌握 Agent 开发**。

## 代码语言切换

示例代码以 **Python** 为主，同时提供 **Go** 和 **Java** 版本。有多语言代码的地方，代码块上方会有标签页：

```text
┌─────────┬──────┬────────┐
│ Python  │  Go  │  Java  │   ← 点击切换
├─────────┴──────┴────────┤
│ ...代码...               │
└─────────────────────────┘
```

在任意代码块上切换语言后，**全站所有代码块会同步切换**，并记住你的选择。下次打开其他文章，看到的仍然是你选的语言。

几点说明：

- **Python 是 Agent 生态的主力语言**，新框架、新 SDK 通常最先支持 Python。即使你主要写 Go 或 Java，也建议能读懂 Python 示例。
- Go 示例尽量只用标准库，Java 示例基于 Java 17+ 标准 `HttpClient` 和 Jackson，便于理解底层原理。
- 少数内容天然只属于一种语言（例如某个只有 Python 版本的框架），文中会特别说明。

## 准备运行环境

本站调用大模型统一使用 **OpenAI 兼容的 Chat Completions API**。这意味着你可以用 OpenAI，也可以用 DeepSeek、通义千问、Kimi 等提供兼容接口的服务，只需改配置，不用改代码。

所有示例通过三个环境变量读取配置：

```bash
# .env 示例（不要提交到 Git）
OPENAI_API_KEY=sk-xxxx           # 你的 API Key
OPENAI_BASE_URL=https://api.openai.com/v1   # 可选，换成其他厂商的兼容地址
LLM_MODEL=gpt-4o-mini            # 模型名，仅为示例，以厂商文档为准
```

环境的具体搭建步骤见下一模块的 [开发环境：Python / Go / Java](/guide/01-programming/dev-env)。

::: warning 保管好 API Key
不要把 Key 写进代码、截图或提交到仓库。把 `.env` 加入 `.gitignore`。一旦泄露，立即在厂商控制台作废并重新生成。
:::

## 高效学习的建议

1. **读 → 跑 → 改 → 测**。读完概念后把代码跑起来；然后改一处（换个工具、改个提示词），预测结果再验证。预测错了的地方，就是你理解不到位的地方。
2. **养成看「原始消息」的习惯**。调试 Agent 时，把每一轮发给模型的完整 messages 和返回打印出来。绝大多数问题，看一眼上下文就知道原因。
3. **小步快跑，尽早做评估**。哪怕只有 10 条测试用例，也比凭感觉判断「好像变好了」可靠。
4. **善用术语表**。遇到不熟的术语查 [术语表](/glossary)；需要更多资料看 [学习资源](/resources)。
5. **用面试题自测**。学完一个篇章，用 [面试题](/interview/) 检验自己能否把概念讲清楚。

## 常见坑

- **跳过基础直接学框架**。框架版本变化快，底层原理（消息结构、Tool Calling、循环）才是稳定的。
- **只读不练**。Agent 的很多细节（上下文膨胀、工具参数出错、无限循环）只有跑起来才能体会。
- **一次学太多模块**。每学完一个模块，最好做一个小练习或项目再继续。
- **把 Key 硬编码在代码里**。养成用环境变量的习惯，从第一个示例开始。

## 小测

**1. 你是一名有 5 年经验的 Java 后端工程师，想在公司项目里接入 Agent，应该选哪条路径？**

::: details 查看答案
工程师路径。可以速读 00 导读，跳过大部分 01 编程基础，重点学习 03 API、05 Tool Calling、06 Agent 循环、07 上下文工程、09 RAG，并重视 14 评估和 15 生产化。代码语言切换到 Java，同时建议能读懂 Python 示例。另外可以重点看 [Java：Spring AI 与 LangChain4j](/guide/11-frameworks/java-spring-ai)。
:::

**2. 想把示例代码从 OpenAI 切换到其他兼容厂商，需要改什么？**

::: details 查看答案
通常只需修改环境变量：`OPENAI_BASE_URL` 改成厂商的兼容接口地址，`OPENAI_API_KEY` 改成该厂商的 Key，`LLM_MODEL` 改成该厂商的模型名。代码本身不用改。不同厂商对某些参数的支持可能有差异，以厂商文档为准。
:::
