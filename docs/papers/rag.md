# RAG 原始论文

## 论文信息

- 标题：Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks
- 作者：Patrick Lewis、Ethan Perez、Aleksandra Piktus、Fabio Petroni、Vladimir Karpukhin、Naman Goyal、Heinrich Küttler、Mike Lewis、Wen-tau Yih、Tim Rocktäschel、Sebastian Riedel、Douwe Kiela（Facebook AI Research、University College London、New York University）
- 年份：2020（NeurIPS 2020）
- 链接：[arXiv:2005.11401](https://arxiv.org/abs/2005.11401)

## 一句话总结

把一个可检索的外部文档库（非参数记忆）和一个生成模型（参数记忆）组合起来，生成答案前先检索相关文档，并把检索器和生成器一起端到端训练，在知识密集型任务上取得了更好、更可溯源的结果。

## 要解决的问题

预训练语言模型把大量知识存在参数里，但这种"参数记忆"有几个根本问题：

- **难以更新：** 世界上的知识变了，只能重新训练或微调模型。
- **难以溯源：** 模型给出一个答案，你无法知道它依据的是哪份资料。
- **会产生幻觉：** 模型对不确定的知识也会给出流畅但错误的回答。

此前已有一些"检索加阅读"的方法，但多数只能从文档中抽取答案片段，不能自由生成；或者检索与生成分开训练。作者想要一个通用方案：既能自由生成文本，又能利用可替换的外部知识。

## 核心方法

RAG 由两部分组成：

- **检索器：** 基于 DPR（Dense Passage Retrieval）的双塔模型，把问题和文档都编码成向量，用最大内积搜索从 Wikipedia 切分出的大量段落中找出 Top-K 相关段落。
- **生成器：** 一个预训练的 seq2seq 模型（BART），把问题和检索到的段落拼在一起作为输入，生成答案。

```text
                       离线：Wikipedia 段落 ──▶ 文档编码器 ──▶ 向量索引
                                                                │
 在线：                                                          ▼
 ┌──────┐   ┌────────────┐   问题向量   ┌───────────────────────────┐
 │ 问题 │──▶│ 问题编码器  │ ──────────▶ │ 最大内积搜索，取 Top-K 段落 │
 └──────┘   └────────────┘             └───────────────────────────┘
     │                                          │ z1, z2, ... zK
     │                                          ▼
     │                         ┌────────────────────────────────────┐
     └────────────────────────▶│ 生成器 (BART)：问题 + 每个段落 ──▶ 答案 │
                               │ 对 K 个段落的生成概率做边缘化        │
                               └────────────────────────────────────┘
```

论文提出两种变体：

- **RAG-Sequence：** 整个答案基于同一个检索段落生成，再对各个段落的结果加权合并。
- **RAG-Token：** 生成每个 Token 时都可以依据不同的段落，适合需要综合多份资料的答案。

训练时，检索到哪个段落被当作隐变量，问题编码器和生成器一起微调；文档编码器和索引保持固定，避免频繁重建索引。

## 关键实验结论

- **开放域问答：** 在多个开放域问答数据集上，RAG 取得了当时的最好成绩，超过了纯参数模型和只能抽取答案的检索方法。即使正确答案不在检索段落中，RAG 也能生成正确答案。
- **生成更符合事实：** 在问题生成等开放生成任务上，人工评估认为 RAG 的输出比纯参数的 BART 更符合事实、更具体。
- **事实核查：** 在 FEVER 事实核查任务上，接近使用复杂流水线和额外监督的专门系统。
- **知识可以热替换：** 把索引从旧版 Wikipedia 换成新版，不用重新训练，模型就能回答关于新知识的问题。这直接展示了非参数记忆的优势。

## 对 Agent 开发的启发

- **知识放在模型外面。** 企业知识、最新数据、用户私有文档，应该通过检索提供，而不是寄希望于模型记住或频繁微调。
- **检索质量决定答案质量。** RAG 的效果上限由检索器决定。今天工程上的切分、混合检索、重排，都是在提升这一环。
- **可溯源是重要的产品能力。** 答案附带检索来源，用户可以核实，这对企业应用尤其关键。
- **今天的 RAG 和论文里的 RAG 已经不一样。** 论文是端到端训练的检索器加生成器；今天常见做法是现成的 Embedding 模型、向量数据库加大模型 API，组件之间不联合训练。思想一致，实现方式不同。
- **从固定检索到 Agentic RAG。** 论文中每个问题检索一次；今天的 Agent 可以把检索当成工具，自己决定检索什么、检索几次。

## 局限性

- 检索器和生成器需要联合训练，对普通应用开发者门槛较高。
- 文档编码器和索引固定，检索器的能力受限于预训练效果。
- 每个问题只检索一次，无法处理需要多步检索、逐步推理的复杂问题。
- 生成器的上下文长度有限，能利用的段落数量少。
- 检索到错误或有偏见的内容时，生成结果也会出错，模型缺乏判断资料可信度的机制。
