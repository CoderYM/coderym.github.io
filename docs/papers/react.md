# ReAct

## 论文信息

- 标题：ReAct: Synergizing Reasoning and Acting in Language Models
- 作者：Shunyu Yao、Jeffrey Zhao、Dian Yu、Nan Du、Izhak Shafran、Karthik Narasimhan、Yuan Cao（Princeton University、Google）
- 年份：2022（ICLR 2023）
- 链接：[arXiv:2210.03629](https://arxiv.org/abs/2210.03629)

## 一句话总结

让模型以"Thought → Action → Observation"的形式交替推理和调用外部工具，推理帮助制定和调整计划，行动带回真实信息修正推理，二者结合比单独推理或单独行动都更可靠。

## 要解决的问题

在 ReAct 之前，两条研究路线是分开的：

- **只推理**（如 [Chain-of-Thought](/papers/chain-of-thought)）：模型完全依赖自己的内部知识，遇到不知道或记错的事实时会一本正经地编造，而且错误会沿着推理链传播。
- **只行动**：模型直接输出一连串动作与环境交互，但没有显式的思考过程，难以分解目标、跟踪进度，也难以在出错后调整。

作者的问题是：能不能把两者结合起来，让推理指导行动，让行动的结果反过来校正推理？

## 核心方法

ReAct 把模型的每一步输出分成两类：Thought（自由文本的思考）和 Action（对外部环境的调用），环境返回 Observation 后再进入下一轮。

```text
  问题: "某部电影的导演出生在哪个城市？"
          │
          ▼
  ┌───────────────────────────────────────────────────┐
  │ Thought 1: 我需要先查这部电影的导演是谁              │ ◀─┐
  │ Action 1:  search[电影名]                          │   │
  └───────────────────────────────────────────────────┘   │
          │                                              │
          ▼                                              │
  ┌───────────────────────────────────────────────────┐   │
  │ Observation 1: (工具返回) 该片由 X 执导……           │   │  循环直到
  └───────────────────────────────────────────────────┘   │  Action = finish
          │                                              │
          ▼                                              │
  ┌───────────────────────────────────────────────────┐   │
  │ Thought 2: 导演是 X，接下来查 X 的出生地             │ ──┘
  │ Action 2:  search[X]                               │
  └───────────────────────────────────────────────────┘
          │  ……
          ▼
  Action N: finish[答案]
```

实现上非常朴素：用几个人工写好的完整轨迹作为 Few-shot 示例，让模型按同样的格式续写；程序解析出 Action，执行后把 Observation 拼回提示词，再让模型继续生成。

论文在知识类任务上只给模型提供了一个非常简单的 Wikipedia 接口（搜索、在页面中查找、给出答案），在交互类任务上使用文本游戏环境和模拟购物网站的动作空间。

## 关键实验结论

论文在四类任务上做了评估：多跳问答（HotpotQA）、事实核查（FEVER）、文本家居环境中的交互任务（ALFWorld）和网购任务（WebShop）。

- **知识类任务：** ReAct 通过查询外部信息明显减少了事实幻觉，推理过程也更可信、更容易解释。但单独使用时并不总是优于思维链，因为搜索结果不理想时会被带偏。论文发现把 ReAct 和思维链（配合自洽投票）结合，在两种方法之间按条件切换，效果最好。
- **交互类任务：** 在 ALFWorld 和 WebShop 上，仅用一两个示例的 ReAct 就超过了使用大量数据训练的模仿学习和强化学习方法。显式的 Thought 帮助模型分解目标、记住进度。
- **错误分析：** 常见的失败包括反复执行相同动作陷入循环、搜索返回无用信息后无法恢复。

## 对 Agent 开发的启发

- **ReAct 就是 Agent 循环的骨架。** 今天的 Tool Calling 本质上把"解析 Action 文本"变成了结构化的工具调用，但"思考 → 调用 → 观察 → 再思考"的循环没有变。
- **Observation 的质量决定上限。** 论文中很多失败来自工具返回的信息不好，这说明工具设计（返回什么、返回多少、如何报错）和提示词一样重要。
- **必须防循环。** 重复动作是 ReAct 最典型的失败模式，工程上要有最大步数、重复检测和预算限制。
- **推理轨迹是可观测性的基础。** 把每一步 Thought 和 Action 记录下来，出问题时才能定位。
- **混合策略往往比单一策略好。** 能直接回答的就直接回答，需要外部信息时再行动。

## 局限性

- 依赖 Few-shot 示例和固定格式，当时的模型输出格式不稳定时需要额外处理。今天的原生 Tool Calling 已经缓解了这个问题。
- 每一步都要调用一次模型，步骤多时延迟和成本线性增长。
- 一步一步贪心地决策，缺乏全局规划，长任务容易偏离目标。这也是后来 Plan-and-Execute、[Reflexion](/papers/reflexion) 等方法要解决的问题。
- 论文中的工具非常简单，真实环境中工具更多、返回更复杂，难度会显著上升。
