# Reflexion

## 论文信息

- 标题：Reflexion: Language Agents with Verbal Reinforcement Learning
- 作者：Noah Shinn、Federico Cassano、Edward Berman、Ashwin Gopinath、Karthik Narasimhan、Shunyu Yao
- 年份：2023（NeurIPS 2023）
- 链接：[arXiv:2303.11366](https://arxiv.org/abs/2303.11366)

## 一句话总结

Agent 失败后，让模型用自然语言写一段"反思"，说明哪里做错了、下次该怎么做，把这段反思存进记忆并放进下一次尝试的上下文，从而在不微调模型的情况下实现"从试错中学习"。

## 要解决的问题

传统强化学习让 Agent 从失败中学习，需要大量试错样本和昂贵的参数更新，对大模型来说几乎不现实。而像 [ReAct](/papers/react) 这样的 Agent，每次尝试都是从零开始，上一次犯过的错误，下一次还会再犯。

作者的问题是：能不能把"奖励信号"转化成模型能读懂的语言反馈，让 Agent 在几次尝试之内就改进行为？

## 核心方法

Reflexion 由三个角色组成，都可以由大模型扮演：

- **Actor（执行者）：** 根据任务和记忆生成行动，比如一个 ReAct Agent 或代码生成器。
- **Evaluator（评估者）：** 判断这次尝试是否成功。可以是环境给的二值信号、单元测试结果、启发式规则，或者另一个模型的判断。
- **Self-Reflection（反思者）：** 读取失败的轨迹和评估结果，生成一段自然语言的反思，写入长期记忆。

```text
           ┌──────────────────────────────────────┐
           │          长期记忆（反思列表）           │
           │ "上次我没检查抽屉就下结论，应该先……"     │
           └──────────────────────────────────────┘
               │ 读取                    ▲ 写入
               ▼                         │
  任务 ──▶ ┌─────────┐   轨迹   ┌───────────┐  结果  ┌──────────────┐
           │  Actor  │ ───────▶ │ Evaluator │ ─────▶ │ Self-Reflect │
           └─────────┘          └───────────┘        └──────────────┘
               ▲                      │
               │                      │ 成功
               │                      ▼
               │                   结束
               └──── 失败：带着新的反思重新尝试 ────┘
```

关键在于反思的内容不是泛泛的"我做错了"，而是具体的、可执行的改进建议。记忆有容量上限，只保留最近几条反思，以控制上下文长度。

## 关键实验结论

论文在三类任务上做了实验：文本环境中的决策任务（ALFWorld）、多跳问答推理（HotpotQA）和编程（HumanEval 等代码生成基准，以及作者新建的一个高难度编程题集）。

- **决策任务：** 加入 Reflexion 后，ReAct Agent 在多次尝试中的成功率持续上升，而不加反思的基线很快停滞。反思尤其能帮助 Agent 摆脱重复同一错误的循环。
- **推理任务：** 反思同样能提升问答的正确率，即使评估信号只是简单的"答对 / 答错"。
- **编程任务：** 让模型先自己生成单元测试，再根据测试结果反思和修改代码，在代码生成基准上取得了当时很好的成绩，超过了直接使用同一基座模型的结果。
- **消融实验：** 只做"重试"而不写反思，或者只给评估结果而不总结教训，效果都不如完整的 Reflexion，说明"用语言总结经验"本身是有效的。

## 对 Agent 开发的启发

- **评估信号决定反思质量。** 编程任务效果好，很大程度上是因为单元测试提供了明确、可靠的反馈。设计 Agent 时，先想清楚"怎么判断这一步做对了"，比优化提示词更重要。
- **反思是一种特殊的记忆。** 把"经验教训"存下来并在后续任务中使用，是长期记忆的一种实用形式，详见 [记忆的分类](/guide/08-memory/memory-types)。
- **自我检查可以低成本地加进 Agent 循环。** 在 Agent 给出最终结果前，加一步"检查是否满足要求，不满足就修改"，往往能提升质量，参考 [Reflection 自我反思](/guide/06-agent-loop/reflection)。
- **要设置重试上限。** 反思会多次调用模型，成本随尝试次数增加，必须配合 [预算控制](/guide/06-agent-loop/stop-budget)。

## 局限性

- 依赖可靠的评估器。如果评估信号本身不准，比如模型自己生成的测试有错，反思可能会把 Agent 带向错误方向。
- 依赖模型的自我诊断能力。模型不一定能正确找出失败原因，可能"反思"出错误的结论。
- 需要允许多次尝试的环境。很多真实场景（发邮件、下单、改数据库）没有重来的机会。
- 记忆只保留有限几条反思，经验无法在大量任务间长期积累和泛化。
- 多次尝试带来成倍的延迟和成本。
