Chain-of-Thought ​

论文信息 ​

  • 标题：Chain-of-Thought Prompting Elicits Reasoning in Large Language Models
  • 作者：Jason Wei、Xuezhi Wang、Dale Schuurmans、Maarten Bosma、Brian Ichter、Fei Xia、Ed Chi、Quoc Le、Denny Zhou（Google）
  • 年份：2022（NeurIPS 2022）
  • 链接：arXiv:2201.11903

一句话总结 ​

在 Few-shot 示例中不只给"问题 → 答案"，而是给"问题 → 推理过程 → 答案"，足够大的模型就会模仿着先推理再作答，从而在数学、常识和符号推理任务上明显变好。

要解决的问题 ​

当时的大模型在"一步就能答"的任务上表现不错，但在需要多步推理的任务上，比如数学应用题，表现很差，而且单纯把模型做大带来的提升也有限。

之前的改进方法要么需要大量人工标注的推理过程去微调模型，要么需要专门训练一个验证器，成本都很高。作者想知道：能不能只改提示词，不改模型，就把推理能力"引出来"？

核心方法 ​

方法本身非常简单：把 Few-shot 示例里的答案换成"推理步骤加答案"。

text

要点：

  • 不需要训练，只需要手写几个（论文里大约 8 个）带推理过程的示例。
  • 推理步骤用自然语言写，人可以读懂，也便于排查模型错在哪一步。
  • 同一套示例可以复用到同类任务上。

关键实验结论 ​

论文在算术推理（如 GSM8K 数学应用题）、常识推理和符号推理（如字母拼接、硬币翻转）三类任务上做了实验，主要结论：

  • 思维链是一种随规模涌现的能力。 在较小的模型上，思维链提示几乎没有帮助，甚至会生成看似通顺但逻辑错误的推理；只有在模型规模足够大时，提升才明显。
  • 任务越复杂，收益越大。 在一步就能完成的简单题上提升有限，在多步推理题上提升显著。
  • 在 GSM8K 上，最大的模型配合思维链提示，达到了当时的最好水平，超过了此前经过微调的方法。
  • 消融实验说明推理的内容本身很重要。 只让模型输出公式、只输出与推理等长的无意义字符、或者先给答案再写推理，效果都不如完整的思维链。这说明提升不只是来自"多生成了一些 Token"。

对 Agent 开发的启发 ​

  • "先想再做"是 Agent 的基本结构。 ReAct 中的 Thought、各种 Agent 框架中的规划步骤，都可以看成思维链在行动场景下的延伸。
  • 推理过程是调试信息。 让模型把中间步骤写出来，出错时你能定位是哪一步理解错了，这对 Agent 的可观测性非常有价值。
  • 示例比指令更有说服力。 想让模型按某种方式思考，最直接的办法是给它看几个这样思考的例子。
  • 要区分对待推理模型。 今天的推理模型在内部已经做了类似的事，再在提示词里强制要求"一步一步想"可能收益不大，甚至增加延迟和成本。参考 推理模型与扩展思考。

局限性 ​

  • 推理过程写出来不代表它就是模型"真实的"推理依据，推理和答案可能不一致。
  • 推理链可能看起来很合理但结论是错的，不能把它当成正确性的保证。
  • 需要人工写示例，示例的质量和风格会影响结果。
  • 输出更长，意味着更高的延迟和 Token 成本。
  • 结论依赖当时的模型规模，在今天的模型上提升幅度可能不同。

后续工作 Self-Consistency（多次采样思维链再投票）和 Zero-shot CoT（只加一句"让我们一步一步思考"）进一步降低了使用门槛，Tree of Thoughts 则把单条推理链扩展成了树搜索。
