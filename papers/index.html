论文精读 ​

Agent 领域的很多工程实践，比如思维链提示、ReAct 循环、自我反思、检索增强，最早都来自论文。读原始论文能帮你理解这些方法"为什么有效、在什么条件下有效"，遇到框架没覆盖的问题时，你也知道该往哪个方向想。

这里选的 8 篇不追求最新，而是追求影响深远：它们提出的思路已经成为今天 Agent 框架和产品的默认设计。

论文列表 ​

论文年份一句话收获
RAG 原始论文2020把"检索外部知识"和"生成答案"结合起来，让模型的知识可以更新、可以溯源
Chain-of-Thought2022让模型先写出推理步骤再给答案，能明显提升复杂推理任务的表现
ReAct2022推理与行动交替进行，是今天大多数 Agent 循环的原型
Toolformer2023模型可以通过自监督的方式学会何时调用工具、传什么参数
Reflexion2023用语言形式的自我反思代替参数更新，让 Agent 在多次尝试中改进
Generative Agents2023记忆流、反思和规划三件套，奠定了 Agent 记忆系统的基本架构
Tree of Thoughts2023把推理过程变成树搜索，允许探索多条路径并回溯
SWE-agent2024为 Agent 专门设计的交互界面（ACI）对效果的影响很大

建议阅读顺序：Chain-of-Thought → ReAct → Reflexion → Tree of Thoughts → Toolformer → RAG → Generative Agents → SWE-agent。前四篇是"推理与行动"一条线，后四篇分别对应工具、知识、记忆和真实环境中的 Agent。

怎么读论文 ​

不需要逐字读完。工程师读论文的目标是拿到可以用的思路，推荐三遍读法：

text
第一遍（10 分钟）           第二遍（30-60 分钟）          第三遍（按需）
┌──────────────────┐       ┌──────────────────────┐      ┌──────────────────────┐
│ 标题、摘要、图表   │  ──▶  │ 方法部分、提示词示例   │ ──▶  │ 复现：用今天的模型      │
│ 结论              │       │ 实验设置、消融实验     │      │ 和 API 写一个最小版本   │
│ 回答：它解决什么？ │       │ 回答：为什么有效？     │      │ 回答：在我的场景成立吗？│
└──────────────────┘       └──────────────────────┘      └──────────────────────┘

读的时候带着几个问题：

  • 问题是什么？ 之前的方法哪里不行？
  • 核心思想能用一句话说清吗？ 说不清说明还没读懂。
  • 实验比较的是什么？ 基线是谁，提升来自哪里，消融实验去掉了什么。
  • 前提条件是什么？ 很多论文结论依赖当时的模型规模或特定任务，换到今天的模型上未必成立。
  • 对我有什么用？ 能不能变成一段提示词、一个循环结构或一条工程规范。

注意时效性

这些论文发表时使用的模型，能力和今天的模型差距很大。论文里"某方法提升了多少"的结论，在今天的模型上幅度可能完全不同，有些技巧甚至已经被模型内化（比如推理模型自带思维链）。学习重点是思想，而不是具体数字。

每篇精读的结构 ​

每篇文章都按同样的结构组织：论文信息、一句话总结、要解决的问题、核心方法、关键实验结论、对 Agent 开发的启发、局限性、相关文章。如果时间有限，优先看"对 Agent 开发的启发"一节。

论文原文都在 arXiv 上免费获取。
