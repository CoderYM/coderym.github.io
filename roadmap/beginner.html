零基础入门路径 ​

这条路径适合没写过程序、或者只写过少量脚本的同学。节奏按每周投入 8 到 10 小时估算，总共约 16 周。前 4 周看起来和 Agent 没什么关系，但它决定了你后面能不能自己调通代码，请不要跳过。

语言选择

零基础建议只学 Python。文章里的 Go / Java 代码标签页可以先忽略，等你熟练后再回头看。

阶段 1：基础准备（第 1-4 周） ​

目标：能独立写一个调用 HTTP 接口、解析 JSON、处理错误的 Python 小程序。

必读：

  • Agent 到底是什么
  • Agent、Chatbot 与 Workflow 的区别
  • 如何使用本站学习
  • 开发环境：Python / Go / Java（只看 Python 部分）
  • Agent 开发必备 Python：建议配合任意一门 Python 入门教程，花 2 周把基础语法练熟
  • HTTP、JSON 与 REST API
  • 数据校验：pydantic / struct tag / record（只看 pydantic）

可以先跳过：异步与并发编程、流式输出与 SSE，阶段 2 用到时再读。

练习：用 requests 或 httpx 调用一个公开 API（比如天气或汇率），把结果整理成表格打印出来。

自检清单：

  • [ ] 能创建虚拟环境、安装依赖、运行一个 .py 文件
  • [ ] 理解 list、dict、函数、类、异常处理的基本用法
  • [ ] 能说清一个 HTTP 请求由哪几部分组成（方法、URL、Header、Body）
  • [ ] 能把一段 JSON 字符串解析成 Python 对象，并取出嵌套字段
  • [ ] 知道 API Key 不能写死在代码里，会用环境变量读取

阶段 2：大模型与提示词（第 5-7 周） ​

目标：理解大模型的基本工作方式，能写出一个多轮对话的命令行聊天程序，并让模型稳定输出 JSON。

必读：

  • Transformer 的直觉理解
  • Token 与上下文窗口
  • 采样参数：temperature、top_p
  • 第一次调用大模型
  • 多轮对话与消息结构
  • 流式响应实战（此时回头读 流式输出与 SSE）
  • 计费、限流与错误重试
  • 提示词基本原则
  • 系统提示词与角色设计
  • Few-shot 与思维链
  • 结构化输出与 JSON Schema

可以先跳过：推理模型与扩展思考、多模态输入、提示词版本管理与测试。

项目：01 命令行聊天助手

自检清单：

  • [ ] 能解释 Token 是什么，以及为什么对话太长会出错
  • [ ] 知道 temperature 调高、调低分别会带来什么效果
  • [ ] 能说出 system / user / assistant 三种角色的作用
  • [ ] 理解"模型没有记忆，多轮对话靠每次把历史消息重新发过去"
  • [ ] 能写出一个让模型返回固定 JSON 格式的提示词，并用 pydantic 校验结果
  • [ ] 遇到 429 或超时错误时，知道应该重试并加退避

阶段 3：Tool Calling 与 Agent 循环（第 8-10 周） ​

目标：让模型能调用你写的函数，并亲手写出一个不依赖框架的 Agent 循环。

必读：

  • 工具调用原理
  • 实现第一个工具
  • 工具设计原则
  • 工具错误处理与重试
  • ReAct：推理与行动
  • 不用框架手写 Agent
  • 终止条件、步数与预算控制
  • 为什么评估是第一优先级（提前建立评估意识）

可以先跳过：并行工具调用、Plan-and-Execute、Reflection 自我反思。

项目：02 天气日程工具 Agent，学有余力再做 03 手写 ReAct Agent。

自检清单：

  • [ ] 能讲清：模型只负责"决定调用哪个工具、传什么参数"，真正执行的是你的代码
  • [ ] 能为一个函数写出清晰的工具描述和参数 JSON Schema
  • [ ] 能画出 Agent 循环：调用模型 → 执行工具 → 把结果放回消息 → 再次调用模型
  • [ ] 知道为什么必须设置最大步数
  • [ ] 工具报错时，知道把错误信息返回给模型而不是让程序崩溃

阶段 4：上下文、记忆、RAG 与 MCP（第 11-14 周） ​

目标：让 Agent 能基于你自己的文档回答问题，并了解 MCP 如何把工具标准化。

必读：

  • 什么是上下文工程
  • 上下文窗口管理
  • 记忆的分类
  • 短期记忆与会话管理
  • Embedding 与向量语义
  • RAG 全景
  • 文档解析与切分
  • 向量数据库
  • MCP 架构与核心概念
  • 开发一个 MCP Server
  • 框架全景与选型

可以先跳过：压缩与摘要、Prompt Caching、长期记忆、混合检索与重排、GraphRAG、A2A，以及框架模块里除总览外的文章。

项目：04 个人 PDF 知识库，然后 05 开发自己的 MCP Server。

自检清单：

  • [ ] 能说清"上下文窗口有限"对 Agent 设计意味着什么
  • [ ] 能解释 Embedding 为什么能做语义搜索
  • [ ] 能画出 RAG 的两条链路：离线建索引、在线检索加生成
  • [ ] 知道切分块太大、太小分别有什么问题
  • [ ] 能说出 MCP 里 Host、Client、Server 的关系
  • [ ] 自己的 PDF 知识库能回答文档里的问题，并给出引用来源

阶段 5：评估与安全入门（第 15-16 周） ​

目标：零基础路径不追求掌握全部生产化内容，重点是建立评估和安全意识，为后续进阶打底。

必读：

  • 评估集与指标设计
  • LLM-as-Judge
  • Prompt 注入与防护
  • 权限控制与人在环路
  • 为什么需要多 Agent

可以先跳过：多 Agent 编排细节、Coding Agent、服务化与部署，完成本路径后转入 工程师路径 的阶段 4、5 继续学习。

项目：为阶段 4 的 PDF 知识库写一个 20 条左右的评估集，并加上 Prompt 注入防护，或者完成 06 网页研究员 Agent。

自检清单：

  • [ ] 能为自己的 Agent 写出至少 20 条带期望答案的测试用例
  • [ ] 能解释 LLM-as-Judge 的用途和它的偏差风险
  • [ ] 能举例说明什么是间接 Prompt 注入
  • [ ] 知道哪些工具操作应该让人确认后再执行
  • [ ] 能判断一个需求是否真的需要多 Agent

完成后，你已经具备独立开发一个简单 Agent 应用的能力。下一步建议对照 12 周学习计划 的第 10-12 周查漏补缺，或者直接挑战 10 毕业项目：企业知识助手。
